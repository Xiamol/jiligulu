# 1.0.10：问什么，先答什么

本地构建 1.0.10 / versionCode 23，签名不变，覆盖安装保留数据；GitHub 公开 Release 仍为 1.0.0。

## 用户问题与本轮改动

用户原题为「我今年能谈到女朋友吗？桃花如何？」、报数 840。本地程序把「女朋友」中的「朋友」匹配为邀约，旧校验还可能拒绝正确的恋爱回答，随后又显示复杂的错题本地推演。前两版的格式与回归检查不能证明回答质量，这一点本次改为真实模型测试。

- 首屏直接结论、短原因、一条建议；五行与三宫详情默认折叠。恋爱/脱单/桃花、复合、普通朋友分别理解，出行不会被同行朋友或终点聚会抢走类型。目标期限与已发生的条件保留，失物发生在昨天不等于目标期限是昨天。
- 模型只回复 `answer/reason/advice` 三个字符串，不需要重造三宫、关系枚举或回显问题。原盘、原三宫和关系均由本地附加。主题相关性检查主答与短原因，不再强迫每一段复制一组关键词。
- 短原因要说明组合顺序；重复宫可以自然说「两头留连，中间小吉」或「前两段……最后……」。混题、只解释末宫、额外宫名、讲错首尾、保证结果等仍拦截。
- 缓存版本 v5，旧长篇不再命中。相对期限记录起课当地日期，避免同一问今年/明天跨期新起课读旧答案；同一天同问同数及固定原课重看不增加请求。
- 改命绑定具体课：大吉章落下、停留、淡出，主答案立即改成此事的阿噜鼓励版，原回答可切换查看；换题不冒用，重开保留，星座配额独立，不调用额外 AI。旧版已用章却无回执的，可以主动补绘一次，不自动虚构归属。
- 清空问题/报数更方便；查看推演、原解读与换题按钮保持位置。

## 实际模型评估

使用本机已有开发配置，`deepseek-flash`、关闭思考，一题一次 HTTPS，没有自动内容修复。测试问句只含本次原题和合成条件，不传账本、聊天或个人资料。密钥没有输出、进入 Git 或公开 APK。

| 问题 | 报数 | 首答重点 | 单次 HTTP |
| --- | --- | --- | --- |
| 我今年能谈到女朋友吗？桃花如何？ | 840 | 今年有相识/暧昧机会，但确定恋爱偏慢、反复 | 1.44 秒 |
| 笔试已经通过，下周终面能否拿到岗位录用？ | 137 | 终面推进有利，仍须认真对待最后一关和正式通知 | 1.64 秒 |
| 钥匙不见，昨天在家用过，能找回来吗？ | 012 | 初答补了寻找经历、次数与位置，未当合格案例 | 1.58 秒 |
| 周末与朋友出游，车票未买，行程能落实吗？ | 511 | 可逐步落实，优先确认票、时间与分工 | 1.35 秒 |

失物题加强事实约束后另复测一次，1.34 秒，仍出现把前两段说成「两头」的错误。程序新增对应防护，不能把成功 HTTP 或合法 JSON 当回答正确；不合格回答回本地简答，不自动追加付费修复。其它模型或新问题仍可能有差异，不宣称穷尽全部回答质量。

Android API 34 模拟器也使用同一开发配置实际起原题；不是把自编回答塞入缓存。真实应用接收并展示「今年有相识和接触的机会，但真正确定恋爱关系偏慢、容易反复，桃花多停在暧昧或观望阶段」，短原因直接区分「桃花有、谈成难」。查看已保存回答不会请求。点击改命录屏中大吉章可见，结论切换、原回答可回看，原三宫不改。测试后临时配置已按字节还原、秘密备份已删除。
