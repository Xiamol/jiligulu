# 2026-10-02 巡检、缓存与手势优化

范围：AI 请求构造与历史查询、预算周期、统计计算、今天页边界手势；未发布，验收版本保持 0.6.2。同签名覆盖安装，不更改数据库结构，不删除历史。

## 已确认并修改

- 原 60 条滑动历史在长对话中每轮移除开头，导致前缀失配。现在以全会话合格消息数划分批次，在 60～79 条间增长，满批次再整体移动；24 小时仍仅用于读取范围。不能按“24 小时内条数”计算模数，否则早已不在上下文中的旧消息过期也会扰动批次。当前输入仍仅出现一次，草稿/待处理占位不作为历史。
- 昵称与分类按 ID 稳定排序，以 JSON 数据块放在固定系统规则之后、历史之前。时间、账本、待补充状态仍在末尾更新。字段不是指令；固定系统资源原文不变。改昵称/分类会使该数据块之后的缓存重新建立，这是正确行为。
- AI 历史改数据库有界查询，避免每轮把全部聊天记录和卡片载荷加载到 Kotlin。COUNT 仍读取合格记录计数；未声称常量时间查询。
- 普通闲聊/新增不查询不会使用的改删候选；无恢复意图时不查询回收站候选。实际改删返回仍重新校验目标账单。
- 图片分类分支重新抛出取消，避免取消被普通失败吞掉。账本摘要金额固定 Locale.ROOT，避免地区设置改变数字格式。
- 预算长时间订阅跨日/周/月时每分钟检查周期，只在区间改变时重订阅数据库。日/周周期按本地日历午夜计算，涵盖夏令时 23/25 小时。
- 统计日过滤采用 [日初, 次日日初) 时间比较，不再每笔创建 Calendar；仅选择合并分类时计算前六类，柱图复用 Calendar。
- 今天已吸附时，在页面稳定后再向左拖超过页面宽度约 20% 并松手，进入统计。右滑仍看昨天；从昨天滑到今天的同一次手势不会直接进入统计。未吸附、纵向、短拖、多指不会触发。

## 缓存线上构造样本（不含真实账单/聊天）

官方参考：https://api-docs.deepseek.com/guides/kv_cache/
DeepSeek flash，固定系统规则、构造的 60 条中文聊天，4 次请求均返回非空内容：

|请求|命中 token|未命中 token|命中率|
|---|---:|---:|---:|
|旧结构首次 60 条|0|4649|0%|
|旧结构每轮移动窗口|2176|2473|46.8%|
|新结构首次 60 条|2176|2474|46.8%|
|新结构稳定前缀追加为 62 条|4352|366|92.2%|

这是小样本、预热后的结构验证，不是生产平均命中承诺。新安装/新类别/批次裁切/24小时过期/服务端缓存回收仍会影响命中。日志只记录 token 数和比率，不记录请求正文或 Key。
