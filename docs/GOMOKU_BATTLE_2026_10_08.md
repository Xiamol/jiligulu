# 1.0.4 五子棋实际对局与搜索修复

日期 2026-10-08（Asia/Tokyo），本地测试包 1.0.4 / 17。协议不变，可与 1.0.3 对局。未发布新的 GitHub App Release。

## 真实模拟器对局

使用自建 API 34 模拟器、15 路自由五子棋、同屏双人。强辅助一方通过实际装饰入口落子，另一方由 Codex 自己判断并点击棋盘；没有用第二个引擎代替手动一方。棋谱、每步 JSON 与原始截图位于本地 `D:/叽里咕噜/output/android-qa/gomoku-battle/`，`baseline-games.md` 包含完整复盘。

- 第一局，辅助执黑，19 手黑胜。手动白棋拆斜二、横跳二、活三；F5 冲四，辅助准确以 E4 防守。后续黑棋 K9 构成两线威胁，L9 活四、M9 成五。末局白方无法同时封堵两端。
- 第二局，辅助执白，46 手白胜。手动黑棋构造多轴双活二与连续冲四；白棋用 D8、C6 的反冲四争得应手，再化解 K5/K7 跳四，最终发现手动黑方漏看的 G3–F4–E5–D6 斜线活四，以 H2 成五。
- 这两局没有发现漏防即时必胜点；辅助均胜，不能推导对所有真人的棋力或胜率。手动一方存在判断失误，样本很小。
- 安静局面常用满 5000ms。真实电脑 JVM 基准，第一局第2手后（黑方）旧版 I7 / 5012ms，第二局第21手后（白方）旧版 G3 / 5025ms；不是手机耗电或棋力评级。

## 实际发现及修复

1. 正常对局底部零宽 Spacer 的 `boundsInRoot` 返回空矩形，使装饰入口误判无空间并隐藏。加宽测量占位，实际 1080×2400 界面恢复可见和可操作。
2. 战术阶段截止只有全局第16次检查且该次为战术访问才生效；某些访问序列可跳过阶段截止，吃掉后续主搜索预算。现在每次战术访问独立核验阶段时限，取消仍可及时停止。
3. 防守筛查中途超时会丢掉已经证实的败着。现在持久保留确证败着集合，主搜索、候选扩展和最终兜底都过滤这些败着；未检查的着法保持未知，不称作安全。
4. 安静候选先裁剪，可能删除上一轮置换表最佳着。现在合法的最佳着在裁剪前保留。
5. 少空位残局的静态 stand-pat 不能当作可靠下界。剩余不超过4空位时搜索全部合法续着到成五或满盘。

搜索仍有候选剪枝、预算和地平线限制；没有穷尽解决自由五子棋。保持离线、可取消、后台线程计算；默认不写诊断日志或增加用户提示，入口没有新增专属音效。
