# 多轮在线聊天与自动更新修复

基线 4c9a5cf。用户继续反馈普通聊天频繁收到空回复，且自动更新显示旧的手动检查时间。上次增加本地问候只是失败兜底，本次针对真实请求与触发逻辑修正。

## 对比范围与实测

匿名读取 GitHub Releases，最近两次发布确为 v0.5.5（2026-09-22）和 v0.5.4（2026-09-21）。对照本地对应 tag：0.5.4 不带多轮 messages；0.5.5 和当前版会发送多轮历史。模型、API 地址、temperature=0.7、JSON 输出模式相同。

使用同一现有构建账号直连官方 API，全部是合成测试对话，没有读取或上传手机私人账本。复现工具为 `tools/probe_chat_versions.py`；只在内存读取本机构建凭据，不输出凭据、请求头或服务错误正文。模型响应为测试场景数据。

第一组每种形态 4 个请求（hi / 陪我唠唠嗑 / 在嘛 / 那必须的）：

| 请求形态 | 有效在线回复 | 观察 |
| --- | --- | --- |
| v0.5.4，单轮 | 4/4 | 未出现空白 |
| v0.5.5，补齐旧版 system 历史区与本轮重复注入后复测 | 3/4 | 1 次 HTTP 200、finish_reason=stop、内容仅空白 |
| 修复前当前形态，带多轮历史 | 2/4 | 2 次空白 |
| 只把 assistant 历史封装为 JSON | 3/4 | 单独封装仍有空白 |

补充对比：去掉历史 4/4，但会丢掉用户要求的聊天记忆，未采用。只加末轮 JSON 提示及移除 JSON 模式的方案仍出现不合约定的格式，未采用。

初轮旧版 v0.5.5 使用简化 system 历史区，结果为 1/4；该形态不够贴近旧版，不能直接用于宣称旧版故障率。补齐旧版重复注入机制后得到上表 3/4；同批当前修复前形态再次为 2/4。所有比例仅为小样本观察。

采用“历史 assistant 与响应 JSON 格式对齐 + 本轮末尾明确输出协议”后：第一组 4/4，追加重复 16/16；再做 8 轮连续对话全部成功，能回忆“刚才去散步、走了一大圈、很累”。另测 4 个动作请求，新增账单 2/2、提醒设置 1/1、检查更新 1/1，字段仍能解析。

为覆盖用户已存在失败消息的历史，再带入 3 对旧的空响应错误提示，连续聊 8 轮，8/8 正常并保留散步记忆。最终采用形态的普通聊天样本合计 36/36 有效，动作请求另计 4/4；均为直接接口首轮结果，不依赖本地问候或重试凑成功数。

这是有限样本下对请求形态相关性的直接验证，不证明所有旧版曾经稳定，也不能保证第三方服务今后零失败。DeepSeek 官方也明确说明 JSON Output 可能返回空内容：[JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)。

## 代码变化

- 历史 assistant 的发送格式固定为 `{"bills":[],"reply":"原有完整文本"}`，使用 JSON 序列化转义引号与换行。用户历史仍是原始 user 文本。
- 只改发送到模型的协议表示，不回写、删掉或压缩已存聊天，不改变 24 小时 / 60 条窗口；同一历史序列在后续请求中保持确定的字节表示。
- 本轮动态 user 内容末尾附加 JSON 输出要求和闲聊示例，避免紧邻的历史纯文本示例干扰结构化输出。原静态 system 与动态模板 assets 字节保持 9282 / 329，未混入时间或用户信息。
- JSON 结果仍须通过既有本地类型解析、动作白名单和确认卡；没有让模型文字绕过确认直接操作账本。

## 自动更新问题

原实现同时存在 6 小时跳过请求、只监听首次准备完成而不监听返回前台、发现新版不记录检查时间三处行为。现改为 Activity 生命周期进入 STARTED 后检查一次，后台返回会再次检查；内部页面切换和重组不重复，关闭自动检查仍生效。

自动/手动成功检查统一保存实际完成时间，无论有无新版本。失败/取消不更改最后成功时间，页面标签改为“上次成功检查”。不通过只改时间戳伪装检查。

原有两个更新测试把 `ReleaseVersion` 对象字符串误当成版本标签，并因失败路径也写检查时间而误通过；已修复测试输入并增加 `checked=true`、`error=null` 断言，另加冷启动/后台返回生命周期用例。

另修复进程仍存活但 Activity 已重建时的准备判断：不能仅凭进程“曾启动过”就跳过新 ViewModel 的数据准备，否则新页面及依赖 ready 的检查可能永远不启动。新增连续关闭/重新创建 Activity 的真实界面回归。

最终自动验证：269 条测试，0 失败、0 错误、0 跳过；lintDebug 与 assembleRelease 均通过，保留已有 4 个非阻断警告及 2 项信息建议。版本继续保持 0.5.5 / versionCode 8，release 构建、旧签名。本轮未推送 GitHub 或自动安装到手机。
